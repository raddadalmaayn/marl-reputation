## Phase 3 — Table 4 state

### Completion: 180/180 files

`run_baselines.py` targets `{c2,c3,c11} × {armA,armB} × seeds 0–29` = 180 evals, each
writing all three engines. **All 180 exist on zenbook**, seeds 0–29 contiguous with no

### CRITICAL AUDIT: `record_rating_events` — verdict **ON**

**Evidence.** The flag appears exactly once in the entire repo:

```
evaluation/baseline_eval.py:114:        record_rating_events=True,
```

It is **hardcoded `True`** in the `ReputationMARLEnv(...)` constructor call, not read from
config and not exposed as a CLI argument — so it cannot be left at its default by a
dispatch line that forgets it.

**Single code path.** `run_baselines.py` is the only driver, and it shells out to
`baseline_eval.py` via `subprocess.run([sys.executable, ".../baseline_eval.py", "--config",
..., "--ckpt", ..., "--seed", ...])` (line 36) with **no flag override**. There is no
second path that could have produced a baseline file with the flag off. The dispatch
scripts `dispatch_desktop_{1..4}.sh` contain no baseline invocation at all — baselines ran
only from `run_baselines.py`, only on zenbook.

**Conclusion: no cell is invalid on flag grounds.** The NaN results have a different cause
(below), and treating them as a flag failure would be the wrong diagnosis.

### Re-score, not retrain — confirmed

`baseline_eval.py` loads a checkpoint (`tr.load(args.ckpt)`), then runs eval episodes with
`tr.select_action(ag, obs, deterministic=True)`. No optimizer step, no training call. The
env is constructed with `reputation_engine="beta"` so the *same* Beta-driven policy and
adversaries drive every episode; `flat` and `eigentrust` are computed post hoc from
`env._rating_events`. This is a genuine estimator swap at eval on a fixed policy.

**Checkpoint used:** `results/tier1b/sweep/checkpoints/sweep_{c}_{arm}/seed{N}/final.pt`,
**all 180 present on zenbook** (30/30 for each of the six groups). Sample:
`checkpoints/sweep_c2_armA/seed0/final.pt`.

## Completion plan — proposed, NOT executed

The June 16 open item ("Table 4 at 60/180") **no longer exists**: Table 4 is at 180/180.
The options below therefore address the *real* remaining defect — degenerate ρ in C11 —
not a shortfall in run count.

Costing basis: median inter-eval spacing on zenbook was **21 s** (n=176 gaps, mean 22 s,
p90 24 s), single-stream, at `--eval-episodes 20`. zenbook has 20 cores.

### (a) Finish the remaining Table 4 cells on the lab hosts — **0 h, not applicable**
There are no remaining cells. All 180 exist. Re-running the *degenerate* 41 at the same
`--eval-episodes 20` reproduces the same NaN, because the collapse is a property of the
policy and config, not of run length. Note also `baseline_eval.py` skips existing outputs
unless `--force`. **This option cannot deliver anything.** It is also the worst placement:
the four desktops are a live Fabric testbed.

### (b) Pull checkpoints to zenbook and re-run at higher `--eval-episodes` — **~5–6 h serial, ~30–40 min parallel**
No pull is needed: **all 180 `final.pt` are already on zenbook.** Raising
`--eval-episodes` from 20 to ~100 gives each run more chance to break score ties and
yield a defined ρ. Cost ≈ 180 × 105 s ≈ **5.3 h serial**, or ≈ **30–40 min** at 12-way
parallelism on zenbook's 20 cores, plus re-aggregation (seconds). Requires `--force`.
**Risk: it may not work.** If C11's collapse is driven by `adversarial_reward_bonus: 1.0`
and the empty `adversarial_ids` rather than by sampling noise, more episodes will not
create variance that the dynamics do not produce. Budget ~1 h for a 10-seed pilot on
`c11 armA` before committing the full 5 h.

### (c) Ship Table 4 at current n, stated honestly, or move to supplementary — **~2–3 h**
Report per-cell n explicitly (including the hold-rate n of 1–11), flag C11 as n=8/5
matched pairs, and either mark C11 as underpowered in place or move Table 4 to
supplementary. Cost is writing and a caption/footnote pass, not compute.

### Recommendation: **(b) pilot first, then (c) regardless of outcome.**

Run the ~1 h C11 arm-A pilot at `--eval-episodes 100`. If ρ becomes defined for most
seeds, spend the remaining ~4–5 h on the full re-run and get a genuine 30-seed Table 4.
If the pilot stays degenerate, stop — that is itself the finding (C11's parameterization
drives the system to a fixed point where estimator discrimination is undefined), and it
belongs in the text rather than being papered over.

Adopt (c)'s honest-n reporting in **either** case: the hold-rate n of 1 and the
125-of-270 arm-asymmetric ρ coverage in Tables 1–2 need disclosure independently of
anything Table 4 does. That disclosure is the highest-value work here and does not depend
on the pilot.

**Before any of this: commit the toolchain.** The sweep code is untracked on a 73%-full
disk and is the single point of failure for everything above.
